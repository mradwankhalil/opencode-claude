### Pump serialization: a local carry with no upstream path

PR #44 was **closed unmerged** (2026-10-06) and issue #43 was **closed as completed**
on 2026-10-13 without a code change. The maintainer's reason: OpenCode always streams
chat turns, the streaming path releases the bridge on its own, and the buffered
(`stream: false`) resume path is not one OpenCode hits. Our own recheck on the issue
agrees with the first half: no stock streaming leak was reproduced; what remains proven
is the buffered resumed-abort handle leak.

So nothing upstream will ever retire this patch, and "keep until upstream resolves #43"
no longer names an exit. It is carried by local decision. The five pump fixtures fail on
pristine v1.4.1, but they exercise the classes this patch adds, so they show the patch is
absent there, not that a running OpenCode v2 hits the defect. Retire it when someone
shows OpenCode v2 never sends a non-streaming resumed request to this proxy and never
runs two consumers on one continuation; until then it stays, and every rebase must keep
those five fixtures green.

The catalog patch is an upstream issue candidate, not yet filed. Carry the verification
commit too.

## Native v2 model behavior

`Model.Info.variants` is an array of `{ id }` entries. Upstream exposes
`low`, `medium`, `high`, `xhigh`, `max`; its `model.request` hook encodes the
selected variant in the effort header. Keep this native mechanism, not the old
v1 variant object or `GENERATED_VARIANT_KEYS` suppression map.

Since v1.4.0 (#48) upstream `buildProviderModel` gives 1M models a 1,000,000 context
and a 128,000 output limit with **no input limit**; OpenCode's own 10% reserve then
compacts at about 90% (the old 900,000 input limit stacked with it and compacted at
about 81%). Do not reintroduce an input limit in ClaudeModel or in the always-on entries.
The aliases resolve to `claude-fable-5-1`, `claude-opus-5-5`, and
`claude-sonnet-5-5` respectively. Unlike the historical fork's CLI-pass-through
family aliases, these explicit targets must be reviewed when the latest models
advance. Bare pins never drift.

Since v1.4.1 (#42) tool turns run with `permissionMode: "dontAsk"` instead of
`bypassPermissions`: only the bridged OpenCode tools run, anything else is refused.
Not a local patch, but check one tool-using Claude turn after each activation.

## Updating

1. Fetch the new upstream tag; rebase the runtime delta commits onto it and carry
   the verification and tooling commits. Review conflicts; never discard a fix.
   OpenCode loads this checkout as a plugin directory, so while OpenChamber runs do
   the rebase in a clone (same branch name) and leave this checkout alone; the
   source moves in the closed window together with the bundle.
2. Run `bun install` if dependencies changed.
3. Run `node scripts/verify-bundle.mjs` (update the base check when porting).
4. Run each fixture, in Git Bash, with the host runtime flag cleared:

   ```bash
   OPENCHAMBER_RUNTIME= timeout 60 bun test/pump-gate-regression.ts
   OPENCHAMBER_RUNTIME= timeout 60 bun test/iterator-race-regression.ts
   OPENCHAMBER_RUNTIME= timeout 60 bun test/persistent-pump-concurrency-regression.ts
   OPENCHAMBER_RUNTIME= timeout 60 bun test/persistent-continuation-lifecycle-regression.ts
   OPENCHAMBER_RUNTIME= timeout 60 bun test/persistent-park-race-regression.ts
   OPENCHAMBER_RUNTIME= timeout 60 bun test/catalog-exposure-regression.ts
   OPENCHAMBER_RUNTIME= timeout 60 bun test/cross-provider-compaction-regression.ts
   OPENCHAMBER_RUNTIME= timeout 85 bun test/run.ts
   ```

   Also run LSP diagnostics on changed TypeScript files. Only the documented
   Windows/POSIX fixture failures are expected on this workstation: `smoke.ts`,
   `cli-probes-regression.ts`, and upstream's `setup-order-regression.ts` (it fakes
   `claude` with a POSIX shell script on a `/usr/bin:/bin` PATH and ends in `ENOENT`
   after its ordering assertions have passed). A catalog failure is never an exemption.
5. **Never run `bun run build` while OpenChamber is running**: its prebuild
   deletes `dist/`, and OpenCode watches `dist/index.js`, so every open
   location unloads this plugin mid-build and running Claude sessions fail.
   Build a staged bundle instead (typecheck, bundle into
   `../opencode-claude-v2-staged/`, marker check, `lane.json` with commit and hash):

   ```bash
   node scripts/stage-bundle.mjs
   node scripts/stage-bundle.mjs --lane <live checkout>          # from a clone
   pwsh -NoProfile -File scripts/activate-staged.ps1 -Status   # exit 2 = staged, not active
   ```

   With OpenChamber fully closed, `pwsh -NoProfile -File scripts/activate-staged.ps1`
   backs up the live `dist/index.js` and swaps the staged one in; `-Rollback`
   restores the newest backup. It refuses to run while OpenChamber or opencode is up.
6. Only after those checks is the lane safe for a **user-controlled restart**.
   Then verify v2 `opencode models` exposes the bare pins and run one tool-using
   Claude turn. No restart, live Claude request, publish or push is part of this
   procedure's build phase.
